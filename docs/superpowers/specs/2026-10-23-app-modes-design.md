# 개발 모드와 차량 연결 모드 설계

> `2026-10-22-car-tamagotchi-design.md`에 이어지는 기능 설계다. 사용자 요청: "앱 처음 시작할때 dev모드와 진짜 연결했을때 보이는 화면 2개로 쪼개줘". 연결 모드를 신호가 없을 때 어떻게 보이게 할지는 사용자가 "연결 대기 화면"(내 추천 1번)으로 승인했다("응").

## 의도
지금 앱은 가짜 신호와 개발자 도구가 섞인 한 화면이다. 이것을 **개발 모드**(가짜 신호 + 개발자 도구)와 **차량 연결 모드**(개발 도구 없는 진짜 서비스 화면, 차에서 읽은 값만 사용) 두 화면으로 나눈다. 진짜 차량에 올릴 때 개발용 컨트롤이 보이지 않게 하고, 개발 중에는 지금처럼 모든 것을 시험할 수 있게 하는 것이 목적이다.

## 시작 화면과 모드 선택
- 앱을 처음 켜면 **시작 화면**이 나오고 두 버튼 중 하나를 고른다: "개발 모드", "차량 연결". 로고 대신 방 스타일의 캐릭터 한 마리와 짧은 설명을 보여준다. (내 판단)
- 고른 모드는 저장해서 다음부터는 시작 화면을 건너뛴다. 저장된 값이 없거나 알 수 없는 값이면 시작 화면을 보인다. (내 판단)
- 모드를 바꾸는 길: 개발 모드의 개발자 도구에 "시작 화면으로" 버튼. 차량 연결 모드는 연결이 안 된 상태(아래)의 안내에 "개발 모드로 보기" 버튼. 둘 다 저장된 모드를 바꾸거나 지우고 해당 화면으로 간다. 설정 화면은 LLM 계획에서 생기므로 그때 "모드 바꾸기"를 그곳으로 옮긴다(`ponytail:` 주석).

## 개발 모드
- 지금의 화면 그대로: 가짜 신호(`FakeSignalSource`), 정차 스위치, 정차일 때의 개발자 도구, 말 입력, 프리셋, 슬라이더, 친구 바꾸기.
- **기분 상태는 모드별로 따로 저장한다.** 개발 모드의 주행 시뮬레이션과 프리셋이 진짜 캐릭터의 기분을 망치지 않게 한다. 개발 모드는 별도 키(`pet_dev`)를 쓰고 차량 연결 모드는 기존 키(`pet`)를 쓴다. 기존 사용자의 `pet` 값은 그대로 차량 연결 모드의 것이 된다. (내 판단)
- 고른 종(`species`)은 두 모드가 공유한다(어느 모드에서 골라도 같은 친구).

## 차량 연결 모드
- 개발자 도구, 정차 스위치, 프리셋, 가짜 컨트롤은 **전혀 보이지 않는다.** 방(캐릭터, 말풍선, 말 걸기)과 정차일 때의 쓰다듬기, 하트 표지판, 친구 바꾸기(개발 도구 밖의 작은 정차 전용 버튼)만 보인다.
- 신호는 `VehicleSignalSource`의 **실제 구현**에서만 받는다. 실제 Pleos Vehicle SDK와 주행 제한 정보는 이 맥에서 연결할 수 없으므로, 이번에는 자리 구현 `UnavailableSignalSource`를 둔다: 연결 상태는 항상 `UNAVAILABLE`, 주행 제한은 항상 `RESTRICTED`(주행 중으로 취급, 안전한 쪽), 신호 값은 전부 `null`. 이 구현을 실제 SDK 구현으로 바꿔 끼우면 나머지 코드는 그대로 동작한다(`ponytail:` 주석).
- **연결 상태** `ConnectionState { CONNECTING, CONNECTED, UNAVAILABLE }`를 신호 원천이 알려준다. 연결 모드 화면 위쪽에 작은 상태 표시(방 스타일의 알약)를 둔다: CONNECTING "차량과 연결하는 중이에요", UNAVAILABLE "차량과 연결되지 않았어요", CONNECTED는 표시하지 않는다(또는 작은 점만). UNAVAILABLE일 때 안내 아래에 "개발 모드로 보기" 버튼을 둔다(주행 중으로 취급되는 상태에서 화면 조작을 요구하는 것은 아니고 선택 사항이다).
- 연결 전에는 주행 중으로 취급하므로 쓰다듬기, 친구 고르기 화면, 설정은 열리지 않고 캐릭터는 저장된 기분(시간 경과 반영)으로 표정을 짓는다. 말 걸기(주행 중에도 가능), 먼저 말하기, 주행 시작 인사 규칙은 기존과 같다.
- 신호가 `null`이면 게이지는 숨고 표정은 기분만으로 정해지는 기존 규칙을 그대로 따른다.

## 구조 변경 (내 판단)
- `PetViewModel`은 지금 `FakeSignalSource`에 묶여 있다(`ponytail:` 주석). 일반 `VehicleSignalSource`를 받고, 개발용 컨트롤은 선택적인 `DevControls?`(구현: `FakeSignalSource`)로 분리한다. 연결 모드에서는 `DevControls`가 없어 개발 동작(`setParked`, `setFuel`, `applyPreset`, `startDrive`, `setTrip`)은 아무 일도 하지 않는다. 기존 개발 모드 동작과 기존 테스트는 그대로 통과해야 한다.
- 저장소는 모드에 따라 기분 상태 키를 고른다. 모드는 별도 저장(`ModeStore` 또는 기존 저장소에 키 추가)이 `dev` / `connected` 문자열로 저장한다. 그 외 값은 "안 고름".
- `MainActivity`는 저장된 모드로 시작 화면, 개발 화면, 연결 화면 중 하나의 최상위 화면을 고른다. 화면 컴포저블은 `PetScreen`을 재사용하되 개발 도구 표시 여부와 연결 상태 표시를 매개변수로 받는다.

## 목표 / 비목표 / 안티 목표
- 목표: 연결 모드에 개발 요소가 한 군데도 새어 나오지 않는다. 모드를 바꾸어도 캐릭터의 기분이 섞이지 않는다.
- 비목표: 실제 Pleos SDK 연결, 실제 차량 주행 제한 읽기(자리 구현만), 모드 자동 감지, 설정 화면(LLM 계획).
- 안티 목표: 신호가 없는데 "정차"로 취급해서 주행 중에 고르기 화면이나 쓰다듬기가 열리는 것, 개발 모드의 가짜 값이 진짜 캐릭터 상태를 바꾸는 것.

## 테스트
- 순수 로직: 모드 id 해석(`modeFromId`: 정확히 `dev`/`connected`만, 나머지는 안 고름), 모드별 저장 키 선택, 연결 상태 문구 선택 함수.
- ViewModel(가짜 저장소, `UnavailableSignalSource`): 연결 모드는 주행 제한으로 시작하고 `needsPicker`가 열리지 않는다, 개발 동작이 아무 일도 하지 않는다, 기분 저장이 `pet` 키로만 간다, 개발 모드의 변경이 `pet_dev`로만 간다(두 저장소가 섞이지 않음), 값이 전부 `null`이어도 크래시하지 않고 표정은 기분으로 정해진다.
- 시작 화면, 모드별 화면, 상태 표시는 단위 테스트하지 않고 에뮬레이터 스크린샷으로 확인한다(에뮬레이터는 확인할 때만 켜고 끝나면 끈다).

## 남은 위험
- 연결 모드는 이 환경에서 실제 신호로 검증할 수 없다. 실제 SDK 구현을 붙일 때 `ConnectionState`와 주행 제한이 제대로 오는지 확인해야 한다.
- 연결 모드는 항상 주행 중으로 취급되는 자리 구현 때문에 지금은 친구 고르기와 쓰다듬기를 쓸 수 없다. 개발 모드에서 고르면 종은 공유되므로 연결 모드에서도 그 종으로 보인다.

## 빌더에게 맡기는 것
시작 화면의 문구와 배치, 상태 표시 알약의 모양, "개발 모드로 보기"와 "시작 화면으로" 버튼의 위치, 모드 키 이름 세부, `DevControls` 인터페이스 모양.
