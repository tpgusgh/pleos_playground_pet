# 개발 모드와 차량 연결 모드 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱을 처음 켜면 시작 화면에서 "개발 모드"(가짜 신호와 개발자 도구, 지금 화면 그대로)와 "차량 연결"(개발 요소가 하나도 없는 서비스 화면) 중 하나를 고른다. 고른 모드는 저장해 다음 실행에서 바로 연다. 차량 연결 모드의 신호 원천은 이번에는 자리 구현(`UnavailableSignalSource`)이라 연결 상태는 항상 "연결되지 않음"이고 차는 주행 중으로 취급한다. 두 모드는 기분 상태를 따로 저장하고 고른 종은 함께 쓴다.

**Architecture:** 모드 id 해석, 모드별 저장 키, 연결 상태 문구, 자리 신호 원천은 Android 의존 없는 순수 Kotlin(`core/`)에 두고 JVM 단위 테스트한다. `VehicleSignalSource`에 연결 상태를 더하고, 가짜 신호만 하는 동작은 `DevControls` 인터페이스(구현: `FakeSignalSource`)로 이름을 붙여 `PetViewModel`이 선택적으로 받는다(없으면 개발 동작은 아무 일도 하지 않음). 고른 모드는 기존 DataStore 파일의 키 `mode`에 저장하고, `ModeViewModel`이 저장된 모드를 읽어 시작 화면·개발 화면·연결 화면 중 하나를 고르게 한다. 모드별 `PetViewModel`은 `ModeViewModel`이 가진 별도 `ViewModelStore`에 모드 id를 키로 만들고, 모드가 바뀌면 그 저장소를 비워 이전 ViewModel(과 그 `Speaker`)을 정리한다. 화면은 `PetScreen`을 재사용하고 `devTools`, `connection`, `onSwitchMode` 매개변수로 나눈다.

**Tech Stack:** 기존 프로젝트 그대로 (Kotlin 2.0.0, Compose BOM 2024.10.01, lifecycle-viewmodel-compose 2.8.7, coroutines 1.9.0, DataStore Preferences 1.1.1). 새 의존성 없음.

**Spec:** `docs/superpowers/specs/2026-10-23-app-modes-design.md` (기반: `docs/superpowers/specs/2026-10-22-car-tamagotchi-design.md`)

## Global Constraints

- 기존 프로젝트를 이어서 쓴다: minSdk 23, targetSdk 35, JDK 17, 패키지 `com.pleosplayground.drivequest`. Gradle은 항상 `JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`로 실행한다(아래 `./gradlew` 명령 모두).
- 이하 `SRC = app/src/main/java/com/pleosplayground/drivequest`, `TEST = app/src/test/java/com/pleosplayground/drivequest`.
- `core/`는 순수 Kotlin이다. 이 계획에서 만들거나 고치는 `core/` 파일에 Android·Compose import를 넣지 않는다.
- 새 의존성, 새 이미지·폰트 파일을 추가하지 않는다.
- **기존 테스트 138개는 수정 없이 그대로 통과해야 한다.** 기존 테스트는 `PetViewModel(FakeSignalSource(), repo, narrator) { now }`로 만들고 `setParked/setFuel/applyPreset/startDrive/setTrip`을 부른다. 이 호출이 그대로 컴파일되게 보조 생성자를 둔다(Task 2). `TestFakes.kt`에는 새 가짜(`FakeModeStore`)를 더하는 것만 허용한다.
- 차량 연결 모드에는 개발 요소(정차 스위치, 개발자 도구 패널, 프리셋, 슬라이더, "말 입력", 주행 시뮬레이션, "시작 화면으로")가 한 군데도 보이지 않는다.
- 신호가 없거나 연결되지 않았으면 주행 중(`UxState.RESTRICTED`)으로 취급한다. 그 상태에서 쓰다듬기, 친구 고르기·바꾸기, 게이지 표지판은 열리지 않는다(기존 규칙 그대로).
- 커밋: 메시지는 한글(타입 접두사는 영어), 마지막 줄은 `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. 예: `git add -A && git commit -m "feat: ..." -m "Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>"`.
- 저장소는 GitHub 공개 저장소다. 커밋은 저장소의 기본 git 사용자(`tpgusgh`)로 한다. `git -c user.name=... -c user.email=...`나 `--author`를 쓰지 않는다. 어떤 Task에서도 push하지 않는다.
- 스크린샷과 UI 덤프는 저장소 밖(`$TMPDIR/modes-shots/`)에 저장하고 커밋하지 않는다. 리뷰어는 PNG를 Read 도구로 열어 본다.
- **에뮬레이터는 Task 5의 화면 확인 단계에서만 켠다**(사용자 요청: 리소스를 많이 쓴다). Task 1~4, 6은 에뮬레이터 없이 JVM 테스트와 `assembleDebug`로만 확인한다. Task 5는 끝날 때(실패한 경우에도) 반드시 끄고 꺼진 것을 확인한다.

### 에뮬레이터 확인 절차 (Task 5)

```bash
ADB=$HOME/Library/Android/sdk/platform-tools/adb
mkdir -p $TMPDIR/modes-shots
# 켜기 (백그라운드로 실행)
$HOME/Library/Android/sdk/emulator/emulator -avd demo -no-snapshot &
$ADB wait-for-device
until [ "$($ADB shell getprop sys.boot_completed | tr -d '\r')" = "1" ]; do sleep 2; done
# 설치와 실행

$ADB shell pm clear com.pleosplayground.drivequest        # 처음 상태(시작 화면이 뜨는 상태)가 필요할 때
$ADB shell am start -n com.pleosplayground.drivequest/.ui.MainActivity
sleep 5                                                    # 시작 직후 약 4초는 시스템 스플래시가 보인다
# 다시 켜기 (저장된 모드 확인)
$ADB shell am force-stop com.pleosplayground.drivequest && $ADB shell am start -n com.pleosplayground.drivequest/.ui.MainActivity && sleep 5
# 화면 찍기와 누를 위치 찾기
$ADB exec-out screencap -p > $TMPDIR/modes-shots/<이름>.png
$ADB shell uiautomator dump /sdcard/ui.xml && $ADB shell cat /sdcard/ui.xml   # 글자·content-desc와 bounds로 좌표를 찾는다
$ADB shell input tap <x> <y>
# 가로로 볼 때 / 세로로 되돌릴 때
$ADB shell settings put system accelerometer_rotation 0 && $ADB shell settings put system user_rotation 1
$ADB shell settings put system user_rotation 0
# 끄기 (Task의 마지막 단계, 실패한 경우에도)
$ADB emu kill
sleep 5; pgrep -fl qemu || echo "emulator stopped"         # 남아 있으면 몇 초 더 기다려 다시 확인하고, 그래도 남으면 보고한다
```

- 개발 모드에서 개발자 도구, 쓰다듬기, "친구 바꾸기", "시작 화면으로"는 "정차" 스위치를 켜야 보인다. `pm clear` 직후 처음 정차하면 친구 고르기 화면이 먼저 뜬다.
- 찍은 스크린샷은 Read 도구로 직접 보고 판단한다. 보지 못한 항목은 보고서에 그대로 적는다.

### 저장과 모드 상태

| 항목 | 값 |
|---|---|
| 모드 저장 | 기존 DataStore 파일 `drivequest`의 새 키 `mode`(문자열)에 `AppMode.id`. 지우기는 키 삭제 |
| 같은 파일 | `ModeStore`는 `PetStore`와 **같은 `Context.dataStore` 인스턴스**를 써야 한다(같은 파일에 `preferencesDataStore`를 두 번 만들면 실행 중 예외). 그래서 `ModeRepository`/`ModeStore`를 `data/PetStore.kt` 안에 둔다 |
| 기분 키 선택 | `PetStore(context, petKey: String = "pet")`. 두 인스턴스(`pet_dev`, `pet`)가 같은 파일, 같은 `species` 키를 쓴다 |
| 저장 실패 | `PetStore`, `ModeStore`는 잡지 않는다(지금 `PetStore`와 같음). `ModeViewModel`이 잡는다: 모드 읽기 `IOException` → `null`(시작 화면), 저장·지우기 `IOException` → 무시하고 화면의 모드는 유지(`// ponytail: 모드 저장 실패는 무시, 다음 실행에 시작 화면(지우기 실패면 이전 모드)이 다시 뜰 수 있다`) |
| 읽기 전 | `loaded == false`인 동안 화면은 빈 방 색 배경만(시작 화면이 잠깐 뜨지 않게) |
| `choose(mode)` | 읽기가 끝난 뒤(`loaded` 작업 `join`), 지금 모드와 다르면 **먼저** `petViewModels.clear()`, 그다음 `mode = mode`, 그다음 저장 |
| `clear()` | 읽기가 끝난 뒤, `petViewModels.clear()`, `mode = null`, 저장된 모드 지우기 |
| 모드별 `PetViewModel` | `ModeViewModel.petViewModels: ViewModelStore`에 키 `mode.id`로 만든다(`ViewModelProvider(store, factory)[mode.id, PetViewModel::class.java]`). 화면 회전에는 `ModeViewModel`과 함께 살아남고, 모드가 바뀌거나 시작 화면으로 가면 비워져 이전 `PetViewModel.onCleared()`(=`narrator.shutdown()`)가 불린다. `ModeViewModel.onCleared()`도 비운다. 액티비티 기본 저장소를 쓰지 않는 이유: 키 하나만 지울 수 없어서 이전 모드의 `Speaker`가 액티비티가 끝날 때까지 남는다 |
| 개발 모드 조립 | `FakeSignalSource(tickDelayMs = 150)` 하나를 `source`와 `dev`로, `PetStore(context, petKeyFor(DEV))`, `Speaker(context)` |
| 연결 모드 조립 | `UnavailableSignalSource()`, `dev = null`, `PetStore(context, petKeyFor(CONNECTED))`, `Speaker(context)` |

### 화면

| 항목 | 값 |
|---|---|
| 최상위 선택 (`MainActivity`) | `!loaded` → 빈 배경(`Surface`의 방 색 `0xFFFFF1D6`만) / `mode == null` → `StartScreen` / `DEV` → `PetScreen(devTools = true, onSwitchMode = modeVm::clear)` / `CONNECTED` → `PetScreen(devTools = false, onSwitchMode = { modeVm.choose(AppMode.DEV) })` |
| 시작 화면 배경 | 따로 칠하지 않는다(`MainActivity`의 `Surface` 색). `safeDrawingPadding`, 세로 스크롤, 내용이 화면보다 작으면 세로 가운데 |
| 시작 화면 그림 | `PetFace(Face.HAPPY, Species.RABBIT, Modifier.height(..))`: 세로 160dp, 가로 120dp |
| 시작 화면 제목 | "무엇으로 시작할까요?" (`Line` 색, 굵게, 22sp) |
| 모드 카드 | 세로 화면은 위아래(`fillMaxWidth().widthIn(max = 360.dp)`), 가로 화면은 나란히(각 너비 260dp), 간격 16dp. 최소 높이 88dp, 모서리 22dp, 테두리 3dp `Line`, `PillButton`과 같은 3dp 아래 그림자. 카드 전체가 `Role.Button`이고 `semantics(mergeDescendants = true)` |
| 카드 내용 | 개발 모드: 배경 `Yellow`, 제목 "개발 모드"(20sp 굵게), 설명 "가짜 신호로 시험해요"(14sp). 차량 연결: 배경 `Pink`, 제목 "차량 연결", 설명 "차에서 읽은 값으로 키워요" |
| `devTools == false` | "정차" 스위치 줄과 개발자 도구 패널 전체(그 안의 "친구 바꾸기", 프리셋, 슬라이더, "먼저 말하기", "말 입력", 주행 시뮬레이션)를 그리지 않는다 |
| 개발 모드 "시작 화면으로" | 개발자 도구 안, "친구 바꾸기" 옆(같은 `Row`, 간격 8dp)의 같은 모양 `Button`(`Line` 바탕, `Cream` 글자) → `onSwitchMode` |
| 연결 모드 위쪽 머리 | 방 위에 세로로: 상태 알약(문구가 `null`이 아닐 때) → 그 아래 `PillButton("개발 모드로 보기", Yellow, onSwitchMode)`(**`connection == UNAVAILABLE`일 때만**), 간격 8dp, 가운데 정렬 |
| 상태 알약 | 높이 36dp, 흰 바탕, 테두리 3dp `Line`, 모서리 18dp, 가로 안쪽 여백 14dp, 글자 `Line` 14sp 굵게, 누를 수 없음, `semantics { liveRegion = LiveRegionMode.Polite }` |
| 연결 모드 "친구 바꾸기" | 방 아래 가운데 `PillButton("친구 바꾸기", Pink) { changing = true }`, `!devTools && parked && !showPicker`일 때만. 지금과 같은 고르기 화면과 확인 대화상자를 연다 |
| `ponytail:` 주석 | "시작 화면으로"와 "개발 모드로 보기" 버튼 위에 각각 `// ponytail: moves into the settings dialog when the LLM plan creates it` |
| 방 높이 | 지금 식의 `8.dp + SwitchRowHeight`를 `chrome`으로 바꾼다. `chrome` = 개발 모드 `8.dp + SwitchRowHeight`(지금과 같음), 연결 모드 `머리 높이 + 8.dp`(머리가 없으면 `0.dp`). 머리 높이: `UNAVAILABLE` 36 + 8 + 48 = 92dp, `CONNECTING` 36dp, `CONNECTED` 0dp. 가로 화면의 주행 중 연결 화면은 스크롤 없이 들어와야 한다 |

## Review Focus

각 줄의 테스트나 확인은 해당 Task에 포함됨.
1. 차량 연결 모드에 개발 요소가 한 군데도 보이지 않는다 (Task 1 `showDevTools`, Task 4 `devTools` 분기, Task 5 확인 ③).
2. 저장된 모드를 읽기 전에 시작 화면이 잠깐 뜨지 않는다 (Task 3 `nothing_is_shown_before_the_stored_mode_is_read`, Task 4 빈 배경 분기, Task 5 확인 ⑥).
3. 깨졌거나 모르는 저장 모드, 읽기 실패는 시작 화면으로 가고 크래시하지 않는다 (Task 1, Task 3).
4. 중간에 모드를 바꾸어도 상태가 섞이지 않고 이전 `PetViewModel`이 정리된다(그 `Speaker` 해제) (Task 2 두 ViewModel 테스트, Task 3 `petViewModels` 테스트, Task 5 확인 ⑧).
5. 연결 모드는 "신호 없음"을 주행 중으로 취급한다: 쓰다듬기, 고르기 화면, 정차 전환이 열리지 않는다 (Task 1 `UnavailableSignalSource`, Task 2 `connected_counts_as_driving`).
6. 개발 동작은 `DevControls`가 없으면 아무것도 바꾸지 않고 저장도 하지 않는다 (Task 2).
7. "개발 모드로 보기"는 `UNAVAILABLE`일 때만 보인다 (Task 5 코드 리뷰, 확인 ③. 이 환경에서는 `CONNECTING`/`CONNECTED`를 만들 수 없다).
8. 저장된 모드로 다음 실행에서 시작 화면을 건너뛴다. "시작 화면으로"는 저장을 지운다 (Task 3, Task 5 확인 ⑥⑦⑨).
9. 화면 회전에도 고른 화면과 그 ViewModel 상태가 유지된다 (Task 4 구조, Task 5 확인 ②⑤).
10. 기분은 모드별 키로 따로, 종은 함께 (Task 1 `petKeyFor`, Task 2, Task 5 확인 ⑧).
11. 기존 테스트 138개가 수정 없이 통과한다 (모든 Task의 전체 테스트).
